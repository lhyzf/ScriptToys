# UI 自定义控件与方法热更新

`ui\` 下所有 `*.ps1` 文件都会按文件名顺序加载，并由同一个热重载器监听。修改或新增其中的函数文件后，运行中的界面会重新加载全部 UI 方法、读取配置并刷新任务操作区；已有任务和输出标签不会因此关闭。运行中的方法会在下一次调用时使用新版本。

这些文件只能包含未指定作用域的函数定义，不要在文件顶层创建控件或执行其他有副作用的代码。热重载器会先校验所有文件，再统一安装函数并重建操作区；如果语法校验或刷新失败，会提示错误、恢复上一次的方法和操作区。运行期间可以添加函数，但不能删除或重命名已加载的函数；这类变更需要重启界面。

## 添加自定义控件

将控件专用的工厂函数及其私有辅助函数放在单独的 `ui\<control-name>.ps1` 文件中。例如，`scheduled_toggle.ps1` 实现长运行任务的启动/停止按钮，`functions.ps1` 通过 `New-ScheduledToggleButton` 使用它。新增 `.ps1` 文件会自动参与加载和热重载，无需修改监听器。

建议每种控件提供一个有明确名称的 `New-*` 工厂函数，并将状态更新、视觉行为和事件清理等实现细节留在该控件文件中。函数可调用 `functions.ps1` 或其他控件文件中的函数；所有文件会作为同一组定义校验，因此函数名称必须唯一。已有控件实例会在刷新操作区时重建，任务进程和输出标签会保留。

窗口主体、已有输出控件以及 `main_ui.ps1` 中编译的辅助类型不会热更新，修改它们需要重启界面。已经执行的任务脚本也不会因修改 UI 方法而重新启动。

在项目目录运行热更新测试：

```powershell
pwsh -NoProfile -STA -File tests\ui_hot_reload.ps1
```
